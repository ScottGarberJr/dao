# October 2026

## October 2 — Local reconnaissance context limit

### Outcome

A read-only DAO reconnaissance subagent using `ollama/qwen3:4b-instruct` failed before producing a result. The provider returned:

```text
request (4096 tokens) exceeds the available context size (4096)
```

The parent independently inspected the DAO repository, so no DAO decision was based on the failed handoff.

### Decision

At the time, Qwen3 4B was retained only for small, tightly scoped Scout tasks and bounded extraction. That temporary routing decision was superseded on October 7 when the model was replaced and removed. Broad repository or DAO-wide reconnaissance must either:

- use a larger authenticated model; or
- be partitioned into smaller Scout tasks with bounded file scopes.

A failed local reconnaissance run must be reported as incomplete evidence, not treated as a successful inspection. The parent should escalate or repartition the task explicitly.

### Runtime context

This decision applies to the Pi/Herdr environment and does not change the DAO's harness-independent role or methodology definitions. The current model matrix and fallback policy remain subject to later review.

### Outcome

Validation covered:

- direct Ollama text and image input;
- a direct OpenAI-compatible response containing a structured `tool_calls` entry;
- Pi text output;
- Pi image input;
- Pi receiving, executing, and completing a harmless Bash tool call.

`dao-general:9b` embeds a 16,384-token runtime context, temperature 0.2, top-p 0.8, and repetition penalty 1.0. Pi declares text and image input, the same 16,384-token context, and a 4,096-token output limit. The coder profile declares an 8,192-token context and 4,096-token output limit.

### Tool-call finding

The earlier malformed tool call was below Buzz and outside Herdr. A direct request to Ollama using Qwen2.5 Coder 14B returned a JSON-looking function call inside ordinary assistant `content`, without a structured `tool_calls` field. Pi therefore had no tool call to execute. Qwen3.5 9B returned the expected structured field through the same Ollama OpenAI-compatible endpoint and Pi executed it successfully.

### Decision

Use the Qwen3.5-based `dao-general:9b` profile as the default local general-purpose, tool-using, and vision-capable model. Use `dao-coder:14b` for bounded coding work, but do not rely on it for agent tool calling unless it is requalified after an Ollama or model-template update.

## October 9 — Pipeline and job distinction

### Decision

The DevTeam workflow now distinguishes two modes:

- **Pipeline:** the factory path for continuing a project from a version plan or coordinating multiple planned features.
- **Job:** a bounded feature, fix, or ad hoc request that uses the existing project documents and only minor planning adjustments.

If the user has not specified the mode, the Lead asks whether to start a pipeline or treat the request as a job. The Lead may recommend a mode but does not silently expand an ad hoc request into a pipeline.

Jobs still require an isolated branch or worktree, basic tests, Lead review, a commit, and a push. Backend jobs need a smoke test or focused API/command check. UI jobs need a functional test, and UI changes also need before/after screenshots. A PR may be opened later unless the user asks for one immediately; the Lead should ask when that timing is unclear.

### Remaining discussion

The role documents have not yet been rewritten around this distinction. The next documentation pass should decide how much planning, Lead review, and independent Tester work can be combined for low-risk jobs without weakening the basic test and review requirements.

### Follow-up decision

Documentation changes should be committed and pushed often after a clear, coherent update. The Lead does not need to ask before routine documentation commits or pushes, although the user can request a pause or different grouping. Every change, including documentation-only work, uses its own branch or worktree. A PR may be opened later.
