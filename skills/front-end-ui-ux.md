# Front-end UI/UX

## Purpose

Provide a balanced web UI baseline for products and business interfaces when no more extreme visual direction is approved.

## Procedure

1. Confirm the product type, audience, primary task, and direction lock.
2. Prioritize hierarchy, readable content, predictable interaction, responsive layout, and complete states.
3. Reuse the project’s existing components and tokens before introducing new patterns.
4. Verify keyboard access, focus, errors, empty states, and mobile behavior.
5. Run Design Review before polish.

## Boundaries

This is a baseline, not permission to default every project to generic cards, rounded controls, or arbitrary gradients.
